# 演示说明

公开演示使用构造账单，不上传真实数据。运行步骤见根目录README。

## 三分钟演示路线

|步骤|操作|应观察到的行为|
|---|---|---|
|1|导入账单 → 没有账单？先用构造数据体验|65条微信、支付宝记录入账；界面显示构造数据标记|
|2|查看明细与汇总|本人账户1200元双边划转排除，确凿重复副本排除，关闭订单排除|
|3|检查43元部分退款|关联到原消费，继承类别，按9月到账冲减净支出|
|4|核对张同学48元转账|选择“向他人付款，保留”后纳入支出，不作为内部划转|
|5|核对云间商贸139元|模型低置信度请求选择类别；确认后账本更新并产生训练反馈|
|6|处理999元无原订单退款|不能随意关联小额订单，需补充原始账单或排除|
|7|核对两笔24元咖啡与3899元大额消费|同额交易不自动删除，异常大额不直接断言错误|
|8|查看修改记录并撤销一次|原值恢复，问题重新开放；再次确认可完成任务|
|9|导出XLSX|包含核对后、待核对、排除、全部和修改五张表|

## 文字和截图演示

上传data/demo_微信.csv与data/demo_支付宝.csv时分别选择平台和本人账户别名。文件第一行已经标注构造数据，导入时仍应勾选构造数据选项。

文字样例见data/demo_text.txt。OCR测试图为data/demo_screenshot.png，图片本身清楚注明“构造账单测试图（非真实支付截图）”；它是解析测试素材，不是伪造的支付凭证。压缩版为demo_screenshot_blurred.png。OCR输出总是要求人工确认。

## 随手记账演示

在导入窗口的“随手记账”写下“昨天午饭花了二十八块，支付宝付的。今天微信买早餐，忘了写金额。”，勾选构造数据和允许发送原文，点击“理解并生成草稿”。模型会询问缺失金额；补充“早餐十二块五，第一笔午饭改三十”，核对两笔草稿，再确认入账。可刷新检验恢复，接口失败时使用手工编辑。详见 [随记实测](NOTES.md)。

## 对话演示

使用概览右侧的“知账助手”。无密钥时以本地工具回答“退款匹配情况”“哪些需要核对”等问题，并标注“本地”。配置本地API密钥后，需要明确勾选允许发送脱敏汇总，真实调用成功标注“Qwen”，标题下显示配置的模型；不能用本地模板答复冒充模型调用成功。
